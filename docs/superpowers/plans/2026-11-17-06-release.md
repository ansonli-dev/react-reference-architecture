# 工程验证与运行交付实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal** 交付可复现的构建、单副本运行、质量证据和新人阅读路线，并完成真实集成验收或标注其阻塞。

**Architecture** 教学服务可直接在本机运行，发布容器只含 release 产物。真实 v2 联调依赖单独 Compose 与身份配置。文档对应已经运行过的场景和决策。

**Tech Stack** GitHub Actions、Docker、OpenTelemetry、Storybook、Playwright、axe、TanStack Virtual。NestJS 专题独立。

**Spec** [前端设计](../specs/2026-11-17-bookstore-reference-design.md) 第 7 节，[Java 集成设计](../specs/2026-11-17-java-demo-integration-design.md) 第 5 节。

## 全局约束

- 以 D4 为教学交付基线。E1 可与 J7 并行，J8 依赖 E1 容器产物。E3 需 J8 真实证据才标记“完整真实联调通过”。
- 记录性能环境、浏览器/网络、样本数与基线，示例不宣称生产容量。运行环境和日志不输出凭证、PII、完整报价或 payload。
- NestJS 和虚拟化扩展各有独立验收，不阻塞主教学运行。核心应用只保留 Next.js 内置 BFF。

- 执行 Playwright 生产用例前，根据测试 profile 用当前源码运行 `pnpm build` 或 `pnpm build:demo`。RED 和 GREEN 都执行，测试须失败在目标断言。

## 评审关注点

| 触发                                  | 预期                                 | 任务 |
| ------------------------------------- | ------------------------------------ | ---- |
| Java/IdP 不可达时做 release build     | 正常构建，运行时 readiness 有意义    | E1   |
| runtime 伪造 demo 与轻量部署          | 容器仅启动发布产物，教学端点无法用   | E1   |
| 无 Collector 或上游慢                 | 应用保有清晰状态，关键 trace 可选    | E1   |
| 组件只能鼠标操作、脚本忽略 SSR        | 人工键盘与 axe、生产初始 HTML 都验过 | E2   |
| 冻结安装/CI 没真实跑或 Java 只用 stub | 不能标记完整联调通过，报告具体证据   | E3   |

## Task E1 · 发布容器和观测

**文件** `Dockerfile`、`.dockerignore`、`next.config.ts`、`src/instrumentation.ts`、`src/server/observability/{otel,logger}.server.ts`、`docs/operations/{deployment,observability}.md`、健康/就绪实现、`test/e2e/release-smoke.spec.ts`。

**消费** A2/A5、D4。**产出** 单副本 Node 24 standalone，探测和结构化关联字段，J8 可接入镜像。

- [ ] 定义运行用例：干净环境冻结构建、无上游构建、健康 200、ready 按配置 200/503、release 教学入口 404、模拟上游超时有可关联 request/trace 且无敏感字段。自动集成测试可用本地 stub 和可选 OTLP collector。
- [ ] 建多阶段 non-root 镜像，只复制 standalone、public、静态资源和 release 所需文件。构建/运行 env 分离，单副本 cache 标签语义按设计，反向代理保持 Origin 一致并测试流式输出。
- [ ] Node runtime 限定 OTel 初始化，缺 endpoint 时用结构化日志继续。请求 ID 验证或生成，记录采样、超时和 readiness。不打印 JWT/邮箱、token 或 cookie。
- [ ] `docker build -t react-reference-architecture:local .`，启动后验收 release smoke，记录所用 image digest。`pnpm check && pnpm build` 通过后提交 `feat: package and observe the release runtime`。

## Task E2 · 组件叙事、性能和可访问性

**文件** `.storybook/{main,preview}.ts`、`src/features/catalog/ui/book-card.stories.tsx`、`src/features/book-management/ui/book-table.stories.tsx`、`test/e2e/accessibility.spec.ts`、`docs/architecture/{overview,performance}.md`。

**消费** B3/D3 的真实 UI。**产出** 组件展示、axe/键盘验证、记录客户端 JS、首响应和缓存证据。

- [ ] 为实用组件写 default/loading/error 和可操作样例，Storybook 只渲染独立 UI，不依赖真实 Session/Java 或直跑服务器 RSC。以 `pnpm build-storybook` 验证导出。
- [ ] Axe 和手动走纯键盘流程，验证 Dialog 焦点、表单反馈、分页和 locale 切换。测量同一环境冷/热详情的请求数与耗时，比较 SSR 禁用 JS 的可读内容和 hydration 错误，记录至少 3 个样本与数据规模。
- [ ] 执行 `pnpm test:e2e` 的 accessibility 子集，人工记录未覆盖项。提交 `docs: verify component and runtime quality examples`。

**消费** D4、E2。**产出** 可选 TanStack Virtual 和 NestJS 小范围示例。

- [ ] 各示例安装、检查与 smoke，通过后提交 `docs: demonstrate optional scaling patterns`。
