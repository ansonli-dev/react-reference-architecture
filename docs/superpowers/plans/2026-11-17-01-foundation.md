# 基线与契约实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal** 从当前骨架得到可隔离构建、可测试、有双语布局及可执行边界的实例基线。

**Architecture** 发布和教学使用独立构建产物。应用路由负责本地化装配，业务代码留在 feature，服务端访问由组合层装配。

**Tech Stack** Next.js App Router、React Compiler、TypeScript strict、Tailwind、shadcn/ui、next-intl、Zod、Vitest、Playwright、MSW、dependency-cruiser。

**Spec** [前端设计](../specs/2026-11-17-bookstore-reference-design.md) 第 1–5、7 节，[Java 能力矩阵](../../integration/backend-capability-matrix.md)。

## 全局约束

- 以 `origin/main` 的 `9caf4a0` 为起点。Node 24、pnpm 11.25.0、React 19.3.1、TS 6.0.3。现有 Next.js 16.4.3 是勘察起点，A1 升级到已修复的同主版本后再做 A2。每批新增依赖锁定后验证，不为常规安装关闭供应链策略或 peer 校验。
- 同一 checkout 的两套构建串行执行。production Playwright 的每次 RED/GREEN 测试先构建对应 profile，显式 dev smoke 除外。RED 失败落在目标断言，不能以缺浏览器、未启动进程或过期构建代替。发布构建不得打开教学登录和数据。首次页面网络请求才访问后端。
- 根组依赖约束按设计执行。源码生成文件由生成命令维护，格式化与 lint 路径明确排除它们。
- 环境或网络阻塞时写出准确命令、错误与可重试条件，使用境况相同的 fixture 验证可执行部分。

## Task A1 · 固化版本与运行前提（P0）

**文件** `docs/integration/backend-capability-matrix.md`、`docs/adr/0001-application-baseline.md`、`package.json`、`pnpm-lock.yaml`。

**接口** 当前依赖和后端摘要为输入。为后续产出经过核对的运行规格和每批依赖变更的版本记录。

- [ ] 运行 `node --version`、`pnpm --version`、`pnpm install --frozen-lockfile`、`pnpm peers check`、`pnpm check`、`pnpm build`。记录成功、环境阻塞及复现命令。本步预期获得可辨别的基线，不以 README 代替实测。
- [ ] 处理已实测的安全门禁。16.4.3 `pnpm check` 通过，`pnpm build` 在编译后以 SecurityFatalError 退出。`pnpm audit --prod` 命中 [GHSA-mfr8-8qww-v76h](https://github.com/vercel/next.js/security/advisories/GHSA-mfr8-8qww-v76h)，修复线 16.4.5。首选已查到的 stable 16.4.6，执行 `pnpm add --save-exact next@16.4.6` 与 `pnpm add -D --save-exact eslint-config-next@16.4.6`。执行时复核当前公告，确保仍在维护版本线上。重新冻结安装，运行 `pnpm peers check`、`pnpm audit --prod`、`pnpm check` 和 `pnpm build`。已识别的 Next advisory 必须清除，构建退出 0 才进入 A2。记录补丁和锁文件，提交 `chore: patch the Next.js baseline`。
- [ ] 对照 pinned Java SHA 核准列表、详情和只读兼容模式。矩阵保留“源码确认”与“真实 HTTP 已验证”两个证据粒度。补充计划用到的依赖版本候选、发布链接、已知 peer 限制与实际注册表访问结果。
- [ ] 运行 `git diff --check`、`pnpm format:check`，确保计划修改范围可审阅。提交 `docs: record frontend and backend integration baseline`。

## Task A2 · 构建与环境护栏（P1）

**文件** `next.config.ts`、`tsconfig.demo.json`、`src/server/config/runtime.server.ts`、`src/app/api/ready/route.ts`、`scripts/run-app.mjs`、`.env.example`、忽略规则与测试设置 `vitest.config.ts`、`test/unit/runtime-config.test.ts`。

**消费** A1 的版本结果，先安装并锁定 Zod、server-only、Vitest。**产出** `parseRuntimeEnv(env, Profile): RuntimeConfig`、静态 `BOOKSTORE_BUILD_PROFILE`、`pnpm dev:mock|dev:real|build:demo|start:demo`，保留 `build/start` 为发布产物，`GET /api/ready` 返回 200 或带通用 reason 的 503。

- [ ] 写 Vitest 断言：release + 未配 Java 允许首页及 liveness 启动、目录 readiness 503。配置 `JAVA_CONTRACT=v2-integrated` 缺 issuer/baseURL/认证数据库时 fail closed。拒绝非 loopback demo、非法 origin/目录。先跑 `pnpm exec vitest run test/unit/runtime-config.test.ts`，期望目标导出或行为尚未满足。
- [ ] 实现 Zod 配置与启动器。`BOOKSTORE_BUILD_TARGET` 选择 distDir，`BOOKSTORE_BUILD_PROFILE` 是编译期直接可替换常量。发布路径与教学路径的运行配置隔离。`APP_ORIGIN` 只接受明确 origin，`DEMO_DATA_DIR` 只在 demo 使用。构建配置无外部 I/O，按请求解析/校验必要的 runtime env。发布、教学 TypeScript 输出与忽略规则明确分开，`typecheck` 默认用 release 类型，不并发写共用 `next-env.d.ts`。
- [ ] 实现真实 liveness 与 readiness 的职责区别。就绪端点不泄漏连接串或堆栈。A2 可以报告未安装功能，启用的依赖探测由 B1/E1 接线。
- [ ] 运行上述 Vitest、`pnpm check`、`pnpm build`、`pnpm build:demo`。两构建无 Java/IdP/教学数据。`git status --short` 不应出现生成 tsconfig 或产物变更。提交 `feat: isolate release and teaching builds`。

## Task A3 · 双语主题与通用组件（P1）

**文件** 更新 `next.config.ts`、`src/app/page.tsx` 与 `src/app/layout.tsx`（迁至 locale segment）、`src/app/globals.css`。创建 `src/proxy.ts`、`src/i18n/{routing,request}.ts`、`messages/{zh-CN,en}.json`、`src/app/[locale]/{layout,page,not-found}.tsx`、`src/shared/ui/{button,input}.tsx`、`components.json`、`playwright.config.ts`、`test/e2e/shell.spec.ts`。

**消费** A2 的构建命令。先安装并锁定 next-intl、Lucide 和 @playwright/test，安装 Chromium。**产出** `locales=['zh-CN','en']`、`defaultLocale='zh-CN'`、双语布局和 Buttons/Inputs 公共组件。

- [ ] 用 Playwright 写 `localeAndAssets`：`GET /` 在不跟随重定向时 307 至 `/zh-CN`。`/en`→`lang=en`。`/fr/books`→404。`/api/health` 与静态资源无 locale redirect。键盘可到达主题及语言切换。首次可用 `pnpm dev:mock` 启动后跑单 spec，目标路径先失败。A3 先配最小 Chromium 项目与可复现的本地 webServer，A5 扩展为独立产物测试。
- [ ] 迁移根布局，Proxy matcher 只匹配根和允许前缀，Next-intl 禁用 locale detection/cookie 自动跟随，校验不支持的 locale。页面和 layout 的静态路径按 Next-intl 规范调用 `setRequestLocale`。保留健康检查和项目介绍页。
- [ ] 从官方 shadcn registry 固定和记录实际组件来源及版本，安装 Lucide，添加主题变量/暗色切换。上次 CLI 被阻塞，优先已允许的官方来源固定快照和可复现 CLI。仍不可用时记录命令与阻塞，保住默认样式和无障碍组件，组件完整验收待源可达后补。SSR 与 hydration 的初始主题保持一致。
- [ ] 运行 `pnpm check`、两个构建与 shell spec。页面 title、html lang、焦点和资源状态预期通过。提交 `feat: establish localized storefront shell`。
