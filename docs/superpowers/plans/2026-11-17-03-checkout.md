# 教学会话、购物车与结算实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal** 在生产模式教学构建中跑通身份切换、草稿持久化、报价、幂等下单及中断恢复。

**Architecture** 会话和交易都由服务器端口裁决，Zustand 持有不可信的浏览器草稿，React Hook Form 调用类型化 BFF。教学写入以 SQLite 事务保证单机可重放，前端提交协议同时支持 Java 的 202 流程。

**Tech Stack** Next Route Handlers、node:sqlite、Zod、Zustand、React Hook Form、Vitest、Playwright。

**Spec** [前端设计](../specs/2026-11-17-bookstore-reference-design.md) 第 3–6 节。

## 全局约束

- 基于 A2/A4/A5、B1–B3。教学登录只在 demo 编译产物，并且默认 loopback。v1 release 关闭交易/账号能力。
- 写入先校验能力、Origin、当前会话/角色和数据边界。仅本地 DB 拥有价格、库存、交易。禁止透传客户字段。
- 测试使用按运行隔离的 DB。生产和 E2E 不开放可从 HTTP 操纵时间、故障或 fixtures 的入口。

- 执行 Playwright 生产用例前，根据测试 profile 用当前源码运行 `pnpm build` 或 `pnpm build:demo`。RED 和 GREEN 都执行，测试须失败在目标断言。

- [ ] TDD 测试旧存储迁移、乱码恢复、数量 1/99/100、规范化 UUID 后重复、超过 20 种、导入两轮和切账号，`pnpm exec vitest run test/unit/cart-store.test.ts` 先红。E2E 挑书、加购刷新、登录后导入、登出后其他顾客看到自己的草稿。

- [ ] 运行测试、`pnpm check`、生产 demo cart spec，确认服务端无共享用户 store。提交 `feat: persist per-viewer shopping drafts`。

- [ ] 写固定时钟、真实 SQLite 断言：合法 CNY 首册 2×4900 得 9800，过期时间 +10min。bookId 大小写重复、数量 100、21 项、来信价格或身份字段及不受支持币种拒绝。额度/币种不支持、无库存返回约定错，不建立可提交记录。`pnpm exec vitest run test/integration/demo-quotes.test.ts` 先红。

## Task C4 · 提交事务与幂等恢复

**文件** 扩展 `src/features/checkout/{model,server}.ts`、`src/server/{checkout,adapters/demo/checkout}.server.ts`。新建 `src/app/api/v1/orders/route.ts` 的 POST、`src/app/api/v1/order-submissions/[submissionId]/route.ts`、`test/integration/demo-placement.test.ts`、`test/e2e/placement-http.spec.ts`、更新 OpenAPI。

**消费** C3 Quote、C1 SQLite 与用户能力。**产出** `place(actor,quoteId,key): Promise<Submission>`、`getSubmission(actor,id): Promise<Submission|null>`、 `{submissionId,state,order?,reason?}`。

- [ ] 写测试使用两个 SQLite 连接、可控时间及独立进程 barrier。相同 key/quote 并发只写一个订单，原 201 body 可重放。同 key 不同 quote → 409。不同 key 同 quote → 409。A/B 同时抢仅 1 本，恰一笔成功，不能负库存。改价、跨 owner、到期、第二条缺货均不写部分。模拟 commit 后断连再请求同 key。命令 `pnpm exec vitest run test/integration/demo-placement.test.ts` 先红。
- [ ] 使用 `BEGIN IMMEDIATE` 后读幂等、报价、库存，统一保存订单及明细、报价消耗、库存与成功回执。外部 I/O 在事务外。busy timeout 250ms，耗尽返回 503。幂等先查成功记录，再查已消费，最后查过期。版本从 0 起。状态/回执查询仅 owner 可读。
- [ ] 添加 202 受理路径的可控测试 fixture 来证明 client 协议。标准教学下单走 201。模拟异步仅通过受控 fixture 或可编程上游 stub，避免发布可访问的控制路由。
- [ ] 执行事务测试、production demo placement HTTP spec 和 `pnpm check`，并重复重试和无部分写入验证。提交 `feat: make teaching checkout atomic and replayable`。
