# 书籍目录纵向切片实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal** 在教学与真实只读模式打开目录和详情，验证 URL、SSR、运行期数据边界与缓存。

**Architecture** `CatalogPort` 通过 composition 接本地 SQLite 或 Java v1。RSC 直调 public reader，浏览器通过导航更新 URL。Route Handler 按同一业务能力和 DTO 输出 HTTP。

**Tech Stack** Next Cache Components、next-intl、Zod、openapi-fetch、node:sqlite、Playwright。

**Spec** [前端设计](../specs/2026-11-17-bookstore-reference-design.md) 第 2–6 节，[能力矩阵](../../integration/backend-capability-matrix.md)。

## 全局约束

- 基于 A1–A5。先验收教学和 HTTP stub，Java 真机证据单记。运行时读取 Java/SQLite，构建独立于外部环境。
- 页码 1–100，size=12。v1 最大页且满页也无 next，v1 只做分类筛选。q 是教学和 v2 能力。
- 只缓存公开数据。详情、分类列表采用设计中的 key、tag 和 TTL。书籍没有可信封面 URL，使用本地素材。

- 执行 Playwright 生产用例前，根据测试 profile 用当前源码运行 `pnpm build` 或 `pnpm build:demo`。RED 和 GREEN 都执行，测试须失败在目标断言。

## 评审关注点

| 触发                                | 预期                               | 任务   |
| ----------------------------------- | ---------------------------------- | ------ |
| 一页恰 12 条且已到 100 页           | 无非法 next 链接                   | B1、B4 |
| v1 上游返回非法 JSON 或不可表示金额 | 安全 502，不用示例数据冒充真实数据 | B1     |
| 编译环境无 SQLite 文件也无 Java     | 两产物构建成功                     | B3     |
| 后端故障与缺失                      | API 502/504 与 404 明确区分        | B2、B4 |
| 有请求参数或头部变化                | 按定义缓存，个人请求数据不会被缓存 | B2、B4 |

## Task B2 · 公开 reader、缓存与 BFF

**文件** `src/server/catalog.server.ts`、`src/app/api/v1/catalog/books/{route.ts,[bookId]/route.ts}`、`src/app/api/ready/route.ts`、`test/e2e/catalog-http.spec.ts`。

**消费** `CatalogPort`、A2 及 A4。**产出** `readCatalog(locale,query): Promise<BookPage>`、`readBook(locale,bookId): Promise<Book|null>`、能力 `supportsCatalogSearch` 与两条 GET。

- [ ] 在 built-app HTTP fixture 上写失败验证：合法详情及列表返回 200。非 UUID 400 且无上游调用。未知 UUID 404、超时 504。v1 q 是 422。两个 locale、两分类、page1/2 与登录无关数据需覆盖。执行 `pnpm exec playwright test catalog-http.spec.ts` 复现缺路由。
- [ ] 装配端口和 ready probe，只在 server graph。定义 `'use cache'` 的公开 reader，`catalog:lists` 和 `catalog:book:<id>` 标签，详情缓存与分类前十页受限缓存。对高基数关键词查询读 uncached。RSC 与 API 复用 reader，BFF 默认 no-store 保持同一服务端缓存策略。403/404/502 等避免头部和内部系统信息被错误透传。
- [ ] 运行 `pnpm build && pnpm build:demo` 以及上述 Playwright。断言测量缓存命中需控制上游 counter 与 Next 进程，确定重复响应来自同一服务而不是测试 fixture 写死。提交 `feat: expose bounded catalog reads and BFF routes`。

- [ ] 写生产 E2E：无 JS 或直接 HTTP 能在服务器输出中找到实际书名。带 category/page 的 URL 可直接访问。表单筛选重置 page。历史 Back 恢复条件。详情未知显示 not-found。阻断上游时 UI 展示故障与重试。教学与真实 stub 两项目。先运行 `pnpm exec playwright test catalog-journey.spec.ts`，断言缺页面而失败。
