# React 架构参考示例改进规格

「页间书店」集中展示三个读者需要作出的架构决定。每个案例用仓库已有场景说明问题、方案、适用条件和可查证的结果。目录和购书流程提供完整的业务前提，便于比较这些决定在两种运行模式下产生的结果。[评审依据](../../architecture/reference-example-review.md)

## 案例与取舍

- **页面首屏与 HTTP 读取。** RSC 在进程内读取目录，独立 HTTP 调用方经 Route Handler 读取同一数据。文档用页面与 JSON 书目一致、慢请求先发页面外壳两个用例支撑说明。只有页面消费时可直接用 RSC。有独立 HTTP 调用方或浏览器需要单独刷新时，Route Handler 提供可维护的接口契约。
- **状态归属。** 已提交筛选和页码放 URL，未提交的输入留在表单，报价 URL 只保存报价 ID，交易状态由服务端按会话读取。只有多个客户端视图需要共享远端数据并协调刷新时，查询缓存有明确用途。跨区域共享尚未提交的本地草稿是另一项独立需求。
- **有并发与中断的写入。** 购物车通过 `ETag` 和 `412` 避免陈旧标签页覆盖数据。报价固定本次交易输入，提交使用稳定幂等键，`Location` 指向提交状态资源。`202` 表示已受理，`PROCESSING` 才触发有限轮询，`RECONCILE_REQUIRED` 提示等待核对并保留手动重查。仅由本站表单消费的一次写入可以选择 Server Action。需要显式条件写入、幂等重放或独立查询状态时，书店的同源 BFF 能表达这些语义。

根 README 用三个问题索引架构概览，概览就近链接代码、测试、双数据源与缓存策略以及依赖方向。直接索引能复用已实现的纵向流程，使读者在同一个书店案例里看见变化如何传到页面、服务端和测试。只有接口编排需求成立时才增加传输模块。只有多个业务真的消费同一个通用提示时才提取共享 UI。

## 运行模式与证据

Demo 在浏览器 Cookie 下运行 SQLite 交易，按币种报价并同步落单。Release 保留账户购物车草稿，人民币报价与可能异步的提交由 Java Order 管理，Keycloak 会话通过 BFF 建立。README 的截图明确其模式，运行说明指出订单和库存行为差异。

- 页面与 JSON 书目一致、Release 对 Java 的请求次数、Demo 成交后库存更新是三项现有证据。Demo 跨入口缓存复用是实现策略，若要断言命中次数，需要在生产 Demo 同语言、同查询的两条入口上观察底层读取。
- Demo 的首次跨标签加购有 Web Locks 时串行，现有浏览器用例在 Chromium 核对该行为。普通 CI 的 Release 使用目录替身。`/api/ready` 检查运行配置与目录可读性。账户、邮件、PostgreSQL 草稿与 Java Order 协作由真实联调用例覆盖。
- 补真实联调证据时记录前端、后端修订与隔离种子条件。兼容范围以实际运行结果为准。

## 结算恢复

- 提交 POST 或状态 GET 收到 `UNAUTHENTICATED` 时，保留正在确认的 `quote`。用户从 Release 购物车看到明确的登录入口，即使 BFF 原本的会话记录仍能读取购物车。登录继续复用购物车的同站 `returnTo`，回跳目标含原报价 ID。
- 回跳后由 RSC 直接按当前会话读取报价。用户手动继续确认，沿用原幂等键。报价到期后仍可重放已经受理的提交，只有上游返回 `QUOTE_EXPIRED` 才提示重新报价。Demo 使用可控的 401 测试共有表单的 URL 和双语反馈。Release 联调覆盖 BFF 会话仍可读取购物车时收到的操作 401，并经过真实 Keycloak 回跳。
- 请求失败后双语都可阅读，`Checkout.notices` 覆盖允许在页面显示的全部业务提示。处理超过浏览器轮询预算时，用户仍可以按同一报价查询或重试。确认结果以 `PLACED` 且有订单 ID 为准。
- Demo 中已提交而浏览器丢失响应时，回来重试仍只产生一笔订单和一次库存扣减。Release 中同一账户在报价后修改一行，订单成功时 BFF 只清理仍匹配的行版本。改过的行和新版本在请求重放后仍保留。

## 代码边界

- 浏览器的创建报价 POST、提交 POST 和查询状态 GET 使用已有的 OpenAPI 客户端和生成类型。传输模块持有端点、超时、错误解析和响应头读取。Zod 验证影响流程的响应，交互流程负责轮询、反馈与导航。提交状态地址必须符合现有同源资源契约。购物车条件请求、报价 ID 作为幂等键和终态判定沿用已有语义。
- 路由保留参数解析、服务端读与跨 feature 组合。独立变化的结算视图从对应公开入口提供，书封继续由应用层组合。通用重试提示由共享 UI 提供。运行时会话、凭据和后端适配器留在有 `server-only` 标记的依赖链。
- 报价创建与读取、提交和状态查询产生的 5xx 使用同一个响应 `requestId` 写入服务端结构化日志。记录固定操作名、分类状态、错误码、耗时与请求 ID。客户端的结算错误保留该 ID，用户仍收到可本地化的业务反馈。

## 发布验收

静态检查、契约生成检查、单元与集成、Demo 与 Release 生产构建、普通端到端、视觉回归、镜像烟测及兼容 Java 环境中的真实浏览器联调运行通过。预合并评审覆盖 spec、实现计划、各批次和最终分支差异。功能分支经 CI 后合入 `main`，核对远端合并提交。
